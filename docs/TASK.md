# Задание хакатона (НИЦ Smart City): «ИИ-помощник по прогулкам в городе Астана»

На входе — набор данных по POI города с короткими описаниями. Нужно придумать и показать рабочую RAG-систему (концепция + демо), которая в реальном времени подсказывает пользователю, куда сходить и что сделать в зависимости от текущей локации, предпочтений и контекста.

**Датасет команда собирает сама, сбор должен быть автоматизирован.**

## Что сдать
1. Концепция продукта — идея, ЦА, сценарии.
2. Демо/прототип — интерактивно, на нескольких сценариях (UI или чат).
3. Высокоуровневое описание RAG-подхода.
4. Набор тестовых сценариев — кейсы, входные данные, ожидаемый тип ответа.
5. Презентация 5–7 минут: бизнес-идея, ограничения, риски, план развития.
6. Этические и privacy-заметки: конфиденциальность локации, недостоверная информация, безопасность.

Формат: репозиторий/архив, презентация PDF, документ с тестовыми сценариями и ограничениями, демо-видео на YouTube по ссылке.

## Данные POI
Название, координаты, короткое описание, категория/теги, часы работы и контакты (если есть), рейтинг/популярность (если есть).

## Примерные сценарии
- «Я сейчас возле Mega Silk Way, хочу прогуляться 30–60 минут — что посоветуете?»
- «Хочу тихое место с кофе и розеткой недалеко от меня.»
- «Еду с ребёнком — где рядом есть детские площадки или музей с интерактивами?»
- «Я — турист, у меня 2 часа перед вылетом: что можно посмотреть поблизости?»
- «Ищу необычную ночную активность (последние пару часов).»

Для каждого: 1–3 конкретных пункта с кратким «почему», примерным временем на посещение и «что делать там» (действие/маршрут/рекомендация).

## Критерии оценки (по убыванию важности)
1. Релевантность и полезность рекомендаций.
2. Контекстуальность и адаптивность — расстояние, время, категория пользователя, ограничения (время в пути, режим работы).
3. Качество объяснений — краткое «почему».
4. UX / понятность демо.
5. Креативность и фишки — фильтры, сценарии, игровые элементы, микро-маршруты.
6. Этика и приватность — минимизация хранения координат, прозрачность, работа с недостоверной информацией.
7. Завершённость — документация, тестовые сценарии, презентация.

## Требования
- Явно указывать, какие данные используются (локация, фильтры, теги).
- Не утверждать уверенно «открыто сейчас», если данных нет — указывать степень уверенности.
- Честно помечать источник: данные POI vs. сгенерированная идея.

## Пример вывода
Вход: «Я у здания Экспо 2017, хочу что-то необычное на 1–2 часа, пешком.»
1. Место (300 м, 5 мин пешком). Почему: … План: 40–60 мин, затем …
2. Место (450 м). Почему: … План: 20–30 минут …

## Советы организаторов
- 2–3 сильных сценария вместо попытки покрыть всё.
- Короткие конкретные ответы лучше длинных рассуждений.
- Описать обработку сомнительных/неполных данных (закрытые места, временные мероприятия).

## Стретч-цели
Групповые рекомендации (3–5 человек), мини-маршрут из 3 мест, мультиязычность, локальные события, доступность для людей с ограниченной подвижностью.
