# Seruen — RAG-бэкенд (FastAPI)

API строго по [`contracts/api.md`](../contracts/api.md): `POST /api/recommend`, `GET /api/pois` (`?fields=lite` — только id, name, lat, lon, category, opening_hours для точек на карте, в ~6 раз легче), `GET /api/presets`, `GET /api/health`, `POST /api/where` (ориентир и адрес по базе: `{"lat","lon","lang"}` → `{"label": "у «Байтерек», бульвар Нуржол, 14", "landmark", "address", "precision_m": 100}`; координаты не уходят наружу и не пишутся в журнал), `GET /api/category-photos` (отдаёт `data/category_photos.json`; нет файла — `{"hero": [], "categories": {}}`).

Фото: поле `image` (Wikimedia Commons с автором и лицензией) идёт из POI в `recommendations[]` и `/api/pois` как есть или `null`; в LLM не передаётся.

## Запуск (из корня репозитория)
```bash
python3.12 -m venv .venv
.venv/bin/pip install -r backend/requirements.txt
cp .env.example .env
.venv/bin/uvicorn backend.app.main:app --reload --port 8000
```
Без ключей LLM сервис работает в **режиме деградации**: ранжирование + шаблонные «почему»/«что делать» и предупреждение в `warnings`, `llm.provider = "none"`.

Тесты (без сети и без LLM, LLM-путь проверяется фейковым провайдером):
```bash
.venv/bin/python -m pytest backend/tests -q
```

Проверка LLM-пути на всех пресетах + запросах kk/en (задержка, JSON, язык), нужен ключ в `.env`:
```bash
.venv/bin/python -m backend.scripts.check_llm
```

## Переменные окружения (`.env`)

|---|---|---|
| `LLM_PROVIDER` | `gemini` | `gemini`. Без ключа → деградация |
| `GEMINI_MODEL` | `gemini-3.5-flash-lite` | модель генерации и разбора запроса |
| `GEMINI_EMBED_MODEL` | `gemini-embedding-2` | эмбеддинги (поддержан и `gemini-embedding-001`) |

| `LLM_TIMEOUT_S` / `LLM_PARSE_TIMEOUT_S` | 6 / 2.5 | бюджет времени на LLM (дальше — деградация) |
| `GEMINI_PARSE_MODEL`, `GEMINI_FALLBACK_MODELS` | 3.1-flash-lite; 3.5-flash-lite,2.5-flash-lite,3.5-flash,2.5-flash | бесплатный тариф ~5 запросов/мин на модель: разбор — своя модель, при 429 — следующая из списка |

## Конвейер `/api/recommend` (`app/pipeline.py`)
1. **Разбор запроса** — `parse.py`: правила на регулярках (всегда: бюджет «30–60 минут»/«2 часа», дети, тихо, кофе, розетки, ночь, вылет, −20…) + LLM в JSON-режиме (t=0) параллельно с погодой. LLM только дополняет правила, мусор отбрасывается. Явные `filters` UI важнее текста.
2. **Жёсткие фильтры (код)** — `rank.hard_filter`: haversine; пешком 4.5 км/ч × 1.3, машина 30 км/ч × 1.2 + 5 мин; радиус = дорога в одну сторону ≤ 33 % бюджета (45 % если цель — прогулка); часы работы на момент *прихода* и хватит ли времени на визит; без часов ночью скрываются закрытые по типичным часам категории (музей и т. п.); дети / доступность / только помещения / категории. Мало мест → радиус расширяется (×1.6, до 3 раз) с предупреждением. «Скоро вылет» → режим такси, запас 60 мин, учитывается дорога обратно в аэропорт.
3. **Поиск** — `search.py`: BM25 (свой стеммер + русские синонимы тегов) + эмбеддинги Gemini (кэш `data/cache/emb_*.npy`, запросы кэшируются в памяти), гибрид 50/50. Без ключа — только BM25.
4. **Ранжирование** — `rank.rank`, веса в `config.WEIGHTS`: релевантность 0.40, мягкие пожелания/интент 0.20, близость 0.15, рейтинг/популярность 0.10, data_quality 0.05, уверенность в часах 0.10, погода ±0.10 (Open-Meteo по центру города, кэш 15 мин; при сдвинутом времени демо — климатическая норма месяца; температура из запроса важнее), время суток ±0.10. Разнообразие: штраф за повтор категории. В LLM уходит top-9.
5. **Генерация** — `generate.py`: LLM видит только кандидатов (id, факты, расстояние, часы и уверенность) и возвращает JSON `{recommendations:[{poi_id, why, what_to_do, visit_min}], ideas:[…]}`.
6. **Валидатор** — `validate.py`: удаляет `poi_id` не из кандидатов (с предупреждением), пересчитывает `distance_m`/`travel_min`/`open_status` кодом, обрезает тексты (200/250), вырезает «открыто сейчас», если статус не `open`; пусто → top-3 с шаблонными текстами.
7. **Маршрут** — `route.py`: ближайший сосед от старта, урезание под бюджет, геометрия OSRM (foot/car) или `straight_line`.

Уверенность в часах (`hours.py`): `high` — 2GIS/офиц. сайт, проверено ≤ 30 дней; `medium` — OSM/ручные; `low` — нет часов или данные старше года. Нет часов → `unknown` + `low`, текст «уточните перед выходом» (для открытых территорий — «обычно доступна»).

## Явные потребности (`app/needs.py`) — жёсткий фильтр релевантности
- Словарь ru/kk/en: бассейн/плавать/аквапарк/pool → `swimming`; фитнес/спортзал/gym; сауна/баня/спа; каток; боулинг; квест; караоке; кино; музей/выставка; театр; парк; бар; ночной клуб; детская площадка; мечеть/храм; магазины: 24/7, супермаркет (бренды Magnum/Small/Galmart), одежда (+«недорого» → тег `budget`), канцтовары, книги, электроника, аптека, ТЦ; и занятия, которых может не быть в городе (горные лыжи, серфинг, дайвинг, скалодром, гольф, зоопарк/океанариум, батуты, пейнтбол, верховая езда). LLM-разбор может добавить ключи только из этого словаря.
- Если потребность названа — кандидаты ТОЛЬКО подходящие (категория, тег или название; для wellness нужен тег/название). Ранжирование: близость, потом рейтинг/популярность.
- Рядом нет → поиск до 10 км на такси и warning «Пешком рядом нет: ближайший … N км». В базе нет → 0 рекомендаций и warning «В нашей базе нет мест для: …». Никаких кафе-заглушек.
- Магазины (supermarket/convenience/clothes/shop/pharmacy) не попадают в досуговые запросы; для покупок why короткий и практичный, `budget` — «сеть с невысокими ценами (оценка)», маршрут — только если просили.

## Индекс эмбеддингов (`data/cache/`)
- Файл `data/cache/emb_store_<модель>.npz`: вектор по ключу `sha1(модель | 768 | текст документа)`. Актуальность проверяется **по содержимому** (хэш текста каждого POI), не по времени изменения: неизменённые места не пересчитываются, изменённые/новые — досчитываются.
- Старт не ждёт индекса: сервис сразу работает на BM25, `/api/health` отвечает (`embeddings: false`, `embeddings_progress: "N/M"`); индекс строится в фоновом потоке батчами по 100 текстов (`batchEmbedContents`), прогресс сохраняется после каждого батча, на 429 — пауза по `retryDelay`. Одинаковые тексты встраиваются один раз; сначала — популярные места.
- Встраиваются только досуговые места (магазины, детские площадки и места с общими названиями вроде «Аптека» обслуживает фильтр потребностей + BM25) — для 3070 POI это 1383 уникальных текста.
- Суточная квота кончилась → если готово ≥ 30 % — частичный индекс (у мест без вектора нейтральная семантическая оценка), иначе BM25; поток ждёт сброса квоты и досчитывает сам.
- Несколько процессов не строят одновременно (lock-файл `emb_build_<модель>.lock`).
- Эмбеддинг запроса: кэш в памяти, бюджет 2 с; 429/таймаут → тихо BM25.
- `data/cache/` в `.gitignore` — для образа его нужно включить явно.

## Демо-фишки
- `weather_override: {"temp_c", "wind_ms"}` в запросе подменяет Open-Meteo, в `context_used.weather` — «(симуляция)». Пресет «Зимний вечер» несёт его сам.
- Пресеты содержат `mode` и `icon`.
- Место, где пользователь уже стоит (метка локации/запрос + < 250 м), при прогулке не рекомендуется — уходит в `ideas` как запасной вариант.
- Факты в why: в промпте — список `facts` кандидата и запрет добавлять удобства/услуги; валидатор вырезает предложения про удобства (бассейн, Wi-Fi, парковка, терраса, ассортимент, «крытый»…), которых нет в данных места.
- Шаблонные `why` (без LLM) объясняют причину выбора (совпадение с запросом, погода, время), а не расстояние.
- Погода: Open-Meteo с таймаутом 2 с, прогрев при старте, при сбое — климатическая норма и повтор не чаще раза в 2 мин.

## Приватность
Координаты огрубляются до 3 знаков и на сервере; в логах — максимум 2 знака; ничего не сохраняется. Погода запрашивается по центру города, а не по точке пользователя.
